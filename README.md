# hgdb-field-workbench · 瀚高项目实施工作台

把散落在 Excel 里的 HGDB 现场实施信息采集表，变成一个**打开就能用**的单文件网页工作台。
核心价值：授权到期自动预警、项目与主机一屏总览、性能基线横向对比。

> 一个 HTML 文件，零依赖、零构建、离线可用。手机浏览器打开后可「添加到主屏幕」当 App 用。

- **仓库**：https://github.com/blatwo/hgdb-field-workbench
- **在线工作台（资料库）**：https://www.workbuddy.cn/space/d/EupwDcuS2LNPSqYY31XHIm
- **数据模型文档**：[`backup/schemas/TABLES.md`](backup/schemas/TABLES.md)

## 一、先看这个：数据安全策略

原始采集表里含**明文数据库口令、内网 IP、MAC 地址、主机 UUID**。本项目采用三层分离：

| 层 | 内容 | 位置 | 是否公开 |
|---|---|---|---|
| 代码层 | `index.html` | 仓库根目录 | ✅ 公开 |
| 示例层 | `data/sample.json`（IP 中段打码、口令清空、主机名虚构） | 仓库 + 内嵌进 HTML | ✅ 公开 |
| 数据层 | `data/real.json`（真实台账） | 仅本机 | ❌ **gitignore 强制拦截** |

**保护措施**：

- `.gitignore` 已锁定 `data/real.json`、`*.local.json`、`backup/`，规则层拦截而非靠自觉
- 页面右上角「脱敏」开关**默认开启**：口令显示为 `••••••••`，IP 显示为 `10.***.26.82`
- 关闭脱敏需手动点击，且会弹出警示
- 本机模式下数据只在浏览器 localStorage；资料库模式下数据在资料库（**公网可访问，请保持脱敏开启**）

⚠️ 若把此页部署到公网，**请保持脱敏开启**。脱敏只是防误看，不等于加密。

## 二、数据架构：10 张关联表（2026-09-10 重构）

原先「一台主机 = 一个扁平对象」的结构已拆分为 **10 张关联表**，存入 WorkBuddy 资料库：

```
项目基本信息 (项目编码)
└── 服务器信息 (主机ID)
    ├── 操作系统信息 1:1
    ├── 磁盘信息 1:N
    │   └── 性能测试 1:N  (主机ID + 磁盘设备)
    └── 数据库信息 1:N
        ├── 数据库安装信息 1:1
        ├── 数据库授权信息 1:1
        ├── 数据库备份任务 1:N
        └── 数据库参数信息 1:N
```

> **⚠️ 关联键必须用「主机ID」**：原始 `资源序号` 跨项目会重复（`G0-S1-1` 出现 7 次），
> 用它做关联会串表。`主机ID` 形如 `p01-G1-S1-1`，全局唯一。

**资料库无原生外键**：类 Notion 多维表，关联靠文本字段存父键 + 页面侧按 key 分组。

**页面接入方式**：保留原有扁平 `state.hosts` 结构，初始化时把 10 张表组装回扁平结构，
因此既有渲染逻辑**零改动**。数据来源优先级：
① 本机自定义数据集 → ② 资料库在线加载 → ③ 脱敏示例数据。

完整表清单、database_id、维护脚本见 [`backup/schemas/TABLES.md`](backup/schemas/TABLES.md)。

## 三、四个模块

### 1. 今天要处理（首屏置顶）
自动聚合三类事项，逾期标红：
- 授权**已过期**的项目
- 授权 **30 天内到期**的项目
- 你自己添加的待办（逾期未完成的**自动顺延到今天**，不会凭空消失）

每条给「标记已跟进」「加待办」一键操作。

### 2. 授权到期预警
按项目聚合并去重，倒计时环 + 三色状态：
- 🔴 已过期　🟠 30 天内　🟢 充足　⚪ 未登记

### 3. 项目总览看板
按项目编码聚合，展示最终用户、ISV、部署架构、主机构成（主/备用色点区分），并附架构分布条形图。

### 4. 主机资源台账 + 性能基线对比
- 台账：支持按项目 / IP / 主机名 / 用途模糊搜索，按架构、芯片、版本筛选，点任意一行看**完整 100+ 字段**详情
- 性能：pgbench TPS 横向排名（10 客户端 / 200 并发两组），自动标注基线最高机型

### 5. 在线录入 / 编辑 / 删除（无需改 JSON）
- 「新增主机」：分 6 组表单录入——① 项目基本信息 → ② 操作系统与数据库 → ③ CPU/内存/网络 → ④ 磁盘（可加多块）→ ⑤ pgbench 性能基线 → ⑥ 数据库优化参数
- 详情抽屉里可对任意主机「编辑 / 删除」（删除有两次确认）
- 编辑时以旧记录为底，导入 JSON 携带的其他列不会丢失；OS 密码编辑时留空 = 保持不变
- 项目级信息（用户 / ISV / 用途 / 架构）按项目填一次，同一项目后续主机可留空；输入框带历史值自动补全
- 录入后立即使示例数据失效，自动切换为「真实数据」模式并存入本机 localStorage

### 从 Excel 转 JSON

原始表约 100 列，建议只映射上表字段即可驱动全部模块，其余字段可保留在 JSON 里留作详情查阅（详情抽屉会自动渲染所有识别到的字段）。

## 五、设计规范（改代码前请读）

| 规则 | 说明 |
|---|---|
| 全内联 | 不引任何外部 CSS/JS/字体/图表库，图标与图表均为手写内联 SVG |
| 调用链单向 | `数据层 → 计算层 → 渲染层`，渲染函数之间**禁止互调**，所有联动走 `refreshAll()` |
| 移动端 | 断点 768px，按钮 ≥36px、输入框 ≥16px（防 iOS 缩放），表格横向滚动，适配 iPhone 底部安全区 |
| 存储键 | 统一前缀 `wb_hgdbfw_`，避免与其它页面冲突 |
| 国内习惯 | 危险红 / 警告橙 / 正常绿；日期 `YYYY-MM-DD` |
