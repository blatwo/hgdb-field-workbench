# hgdb-field-workbench · 瀚高项目实施工作台

把散落在 Excel 里的 HGDB 现场实施信息采集表，变成一个**打开就能用**的单文件网页工作台。
核心价值：授权到期自动预警、项目与主机一屏总览、性能基线横向对比。

> 一个 HTML 文件，零依赖、零构建、离线可用。手机浏览器打开后可「添加到主屏幕」当 App 用。

- **仓库**：https://github.com/blatwo/hgdb-field-workbench
- **在线工作台（资料库）**：https://www.workbuddy.cn/space/d/EupwDcuS2LNPSqYY31XHIm
- **数据模型文档**：[`docs/TABLES.md`](docs/TABLES.md)

## 一、先看这个：数据安全策略

原始采集表里含**明文数据库口令、内网 IP、MAC 地址、主机 UUID**。本项目采用三层分离：

| 层 | 内容 | 位置 | 是否公开 |
|---|---|---|---|
| 代码层 | `index.html` | 仓库根目录 | ✅ 公开 |
| 示例层 | `data/sample.json`（IP 中段打码、口令清空、主机名虚构） | 仓库 + 内嵌进 HTML | ✅ 公开 |
| 数据层 | `data/real.json`（真实台账） | 仅本机 | ❌ **gitignore 强制拦截** |

**保护措施**：

- `.gitignore` 已锁定 `data/real.json`、`*.local.json`、`backup/`，规则层拦截而非靠自觉
- 页面右上角「脱敏」开关**默认开启**：口令显示为 `••••••••`，IP 显示为 `10.***.26.82`
- 关闭脱敏需手动点击，且会弹出警示
- 本机模式下数据只在浏览器 localStorage；资料库模式下数据在资料库（**公网可访问，请保持脱敏开启**）

⚠️ 若把此页部署到公网，**请保持脱敏开启**。脱敏只是防误看，不等于加密。

## 二、数据架构：10 张关联表 + 实体 ID（2026-09-10 重构）

原先「一台主机 = 一个扁平对象」的结构已拆分为 **10 张关联表**，存入 WorkBuddy 资料库。
每个实体有**自己的主键**，子表通过外键字段指向父实体：

```
项目基本信息 (项目ID: PJ01…)
└── 服务器信息 (服务器ID: SRV001…, 项目ID↑)
    ├── 操作系统信息 (服务器ID↑, 1:1)
    ├── 磁盘信息 (硬盘ID: DSK001…, 服务器ID↑)
    │   └── 性能测试 (硬盘ID↑, 1:N)
    └── 数据库信息 (数据库ID: DB001…, 服务器ID↑)
        ├── 数据库安装信息 (数据库ID↑, 1:1)
        ├── 数据库授权信息 (数据库ID↑, 1:1)
        ├── 数据库备份任务 (数据库ID↑, 1:N)
        └── 数据库参数信息 (数据库ID↑ + 参数名, 1:N 竖表)
```

> **⚠️ 为什么不用原始的资源序号做关联键**：台账里的 `seq`（如 `G1-S1-1`）**跨项目会重复**——
> `G0-S1-1` 在 7 个项目里都出现，用它关联会串表。因此改为按序生成的全局唯一 ID，
> `资源序号` 保留为纯展示字段。

**资料库无原生外键**：类 Notion 多维表，关联靠文本字段存父实体 ID + 页面侧按 ID 分组。

**页面读写机制**：对外仍是扁平 `state.hosts`，读写两侧各做一次翻译，渲染逻辑零改动。

| 方向 | 入口函数 | 说明 |
|---|---|---|
| 读 | `assembleHosts(t)` | 10 张表 → 扁平 hosts，同时挂上 `_rid`（各表的记录 id）供写回定位 |
| 写 | `saveHostToLibrary(h)` | 有记录 id 走增量更新，没有就新增并回填 id；子表按 diff 增改删 |
| 删 | `deleteHostFromLibrary(h)` | 级联删除该主机名下全部子表记录 |

- **数据来源优先级**：① 资料库在线（权威源）→ ② 本机 localStorage（离线兜底）→ ③ 脱敏示例数据
- **ID 自动续号**：新增主机时按已有最大序号 +1（`SRV001` → `SRV032`），不会撞号
- **同步状态**：页头指示灯显示「资料库已同步 / 同步中… / 同步失败 / 本机数据」
- **多人协作**：订阅 `db.onUpdated`，他人在数据表里改了数据，页面自动刷新

完整表清单、database_id、维护脚本见 [`docs/TABLES.md`](docs/TABLES.md)。

open index.html          # macOS

## 四、五个模块

### 1. 今天要处理（首屏置顶）
自动聚合三类事项，逾期标红：
- 授权**已过期**的项目
- 授权 **30 天内到期**的项目
- 你自己添加的待办（逾期未完成的**自动顺延到今天**，不会凭空消失）

每条给「标记已跟进」「加待办」一键操作。

### 2. 授权到期预警
按项目聚合并去重，倒计时环 + 三色状态：
- 🔴 已过期　🟠 30 天内　🟢 充足　⚪ 未登记

### 3. 项目总览看板
按项目编码聚合，展示最终用户、ISV、部署架构、主机构成（主/备用色点区分），并附架构分布条形图。

### 4. 主机资源台账 + 性能基线对比
- 台账：支持按项目 / IP / 主机名 / 用途模糊搜索，按架构、芯片、版本筛选，点任意一行看**完整 100+ 字段**详情
- 性能：pgbench TPS 横向排名（10 客户端 / 200 并发两组），自动标注基线最高机型

### 5. 在线录入 / 编辑 / 删除（数据直接落资料库）
- 「新增主机」：分 6 组表单录入——① 项目基本信息 → ② 操作系统与数据库 → ③ CPU/内存/网络 → ④ 磁盘（可加多块）→ ⑤ pgbench 性能基线 → ⑥ 数据库优化参数
- 详情抽屉里可对任意主机「编辑 / 删除」（删除有两次确认）
- **保存即写入资料库**：新增时自动分配 `SRV/DB/DSK` 编号，编辑走增量更新，删除级联清理子表记录
- 编辑时以旧记录为底，表单外的字段不会丢失；OS 密码留空 = 保持不变
- 项目级信息（用户 / ISV / 用途 / 架构）按项目填一次，同一项目后续主机可留空；输入框带历史值自动补全
- 写库失败时降级存本地并如实提示，不会假装保存成功

## 六、设计规范（改代码前请读）

| 规则 | 说明 |
|---|---|
| 全内联 | 不引任何外部 CSS/JS/字体/图表库，图标与图表均为手写内联 SVG |
| 调用链单向 | `数据层 → 计算层 → 渲染层`，渲染函数之间**禁止互调**，所有联动走 `refreshAll()` |
| 移动端 | 断点 768px，按钮 ≥36px、输入框 ≥16px（防 iOS 缩放），表格横向滚动，适配 iPhone 底部安全区 |
| 存储键 | 统一前缀 `wb_hgdbfw_`，避免与其它页面冲突 |
| 读写对称 | 组装（`assembleHosts`）与拆分（`saveHostToLibrary`）的字段映射必须一一对应，改一边要改另一边（用 `test_roundtrip.js` 验证） |
| 国内习惯 | 危险红 / 警告橙 / 正常绿；日期 `YYYY-MM-DD` |

## 七、备份

- **资料库模式**：数据在云端，各端打开即最新，多设备自动同步
- 页面「导出」按钮 → 下载 `hgdb-workbench-YYYY-MM-DD.json`（含主机 + 待办），作为本地快照
- `backup/library_dump/` 存有资料库全量记录快照，可回滚
- 「清空」按钮有**两次确认**，会重新从资料库加载最新数据
